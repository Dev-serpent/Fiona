Getting Started

Fiona can be run directly from a source checkout:

cd Fiona
python3 -m fiona.cli <command>

Examples:

python3 -m fiona.cli edit
python3 -m fiona.cli list
python3 -m fiona.cli camcoms smoke-test
python3 -m fiona.cli phiconnect
python3 -m fiona.cli dataclient

If the console script is installed and on PATH, use:

fiona <command>

Shared GUI

Open the shared Fiona GUI:

python3 -m fiona.cli edit

Panel order:

CamComs -> Vsee -> Bindings -> Raw Json -> Debug -> Host

Panel roles:

  • CamComs: generate identities, export public keys, encrypt/decrypt messages, send encoded envelopes, and run a local smoke test.
  • Vsee: edit 3D points and edges and render connected wireframe shapes.
  • Bindings: edit QuikTieper app launchers and shortcut bindings.
  • Raw Json: edit the QuikTieper config directly.
  • Debug: restricted project file editor for tests, scripts, QuikTieper, and CamComs.
  • Host: inspect host config, trusted devices, key paths, and audit logs.

Web Dashboard

The fionaLocalPages/ directory provides a web-based control dashboard for Fiona — accessible from any browser on your machine. It runs two servers:

  • Flask frontend (port 5000) — serves the pages you see in your browser
  • aiohttp API server (port 8765) — handles all the behind-the-scenes data, WebSocket, and REST API calls

Starting the Dashboard

Use the convenience script (recommended):

./scripts/fiona-pages-start

Or start the servers individually:

python3 fionaLocalPages/server/app.py          # API server (port 8765)
python3 fionaLocalPages/server/flask_app.py    # Frontend server (port 5000)

Opening the Dashboard

Once running, open your browser to:

http://fiona.agent:5000

Tip: If the hostname fiona.agent doesn't work on your system, use http://127.0.0.1:5000 instead.

What You Can Do

  • AI Chat: chat with Fiona's AI assistant, pick different personalities
  • Actions: browse and run Fiona commands, see what's safe to execute
  • Settings: configure ACL rules, shell safety, voice, macros, and more
  • Browser Automation: start a Selenium-powered browser, navigate, click, type, screenshot
  • File Explorer: browse, read, and edit files on your computer
  • Terminal: run shell commands with proper cd tracking (current folder follows you)
  • Performance: live CPU, memory, disk charts
  • RecallVault: search stored information
  • Desktop Awareness: see which window is currently active
  • CamComs: check encryption status and identity
  • And more: notifications, macros, key bindings, plugins, logs, tasks, workspace…

SmartHome / IoT Subsystem

Fiona includes a complete IoT backend stack for home automation simulation. Four packages work together:

Package Role
SmartHome/ Models, device drivers, registry, automation engine
HomeBackend/ REST API + WebSocket + MQTT client service
GNS3Automation/ GNS3 network simulation integration
Laboratory/ Pre-built lab topology, simulated devices, one-command launcher

Quick Start — REST API

# Start the backend service (development mode)
python -m HomeBackend

# In another terminal, test it:
curl http://localhost:8080/api/health
curl http://localhost:8080/api/devices
curl -X POST http://localhost:8080/api/devices \
  -H "Content-Type: application/json" \
  -d '{"device_id":"test-light","name":"Test Light","device_type":"light"}'

Quick Start — Simulated Lab

# Standalone Docker lab (no GNS3 required):
docker compose -f Laboratory/docker-compose.lab.yml up -d

# See all simulated devices publishing to MQTT:
docker compose -f Laboratory/docker-compose.lab.yml logs -f

Quick Start — GNS3 Lab

# Requires a running GNS3 server on localhost:3080
python -m Laboratory --auto-start --discover

What You Can Do

  • Manage devices: Create, read, update, delete smart home devices via REST API
  • Group by rooms: Organise devices into rooms and scenes
  • Automate: Define rules with conditions (time, device state, comparisons) and actions (set state, activate scene, webhook, delay)
  • Simulate: Run 9 simulated IoT devices that publish MQTT readings (temperature, humidity, motion, door, light, switch, thermostat)
  • Monitor: Watch real-time events via WebSocket at ws://localhost:8080/ws
  • Extend: Add custom device drivers, conditions, and actions (see Extension Guide)
